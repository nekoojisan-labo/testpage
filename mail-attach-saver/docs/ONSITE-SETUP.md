## 0. 持ち込み物と前提

- □ キット一式（このフォルダ全体）をUSBメモリ等で現地PCに用意した
- □ 現地PCにインストールされているOutlookが **クラシックOutlook（デスクトップ版・COM対応）** であることを確認した
  - 確認方法: Outlookを開き、リボン右上の「? （ヘルプ）」→「バージョン情報」を確認する。
    または、以下をPowerShellで実行し、COMが取得できることを確認する（**この確認はOutlookを開いた状態で現地PCでのみ実行**）:
    ```powershell
    [Runtime.InteropServices.Marshal]::GetActiveObject("Outlook.Application")
    ```
    エラーにならず何かオブジェクトが返れば、クラシックOutlook（COM対応）が起動中と判断できる。
  - ※「新しいOutlook（New Outlook / Outlook for Windows の新UI）」はCOMに対応していないため、
    本ツールは動作しない。トグルスイッチが「新しいOutlookをオフ」になっていることを見た目でも確認する（9章参照）
- □ 保存先として使う共有ドライブ（Z: 等）に、現地PCから **書き込み権限** があることを確認した
  - 確認方法: エクスプローラーで対象フォルダを開き、テスト用の空フォルダを作成→削除できることを確認する
- □ PowerShellの実行ポリシーが `-ExecutionPolicy Bypass` 付き実行を妨げないことを確認した（管理者権限は不要）

## 2. config.local.ps1 の設定

- □ `config.sample.ps1` の内容と見比べながら `config.local.ps1` を編集した
- □ `$SaveRoot` に実際の保存先パスを設定した（値: ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿）
- □ 上記パスが実在し書き込み可能なことを、設定後に必ず以下で確認した（**事前設定済みの想定でも必ず現地で再確認する**）:
  ```powershell
  Test-Path "Z:\<設定したパス>"
  ```
  結果: □ True（OK） / □ False（→ パス誤り・Z:未接続の可能性。0章に戻って確認）
- □ `$SubjectPatterns` を確認した（追加が必要な場合は3章のDryRun確認後に追記する）
- □ `$RetentionDays`（遡及日数、既定90）を確認した
- □ `$MaxMailsPerRun`（1回あたり上限、既定50）を確認した
- □ 編集後、**必ずUTF-8（BOM付き）で保存されているか**を確認した
  - 注意: メモ帳等で編集して保存すると、環境によってはBOM無しになる場合がある。
    BOM無しで保存すると、日本語コメントを含む行でWindows PowerShellが構文エラーになることがある
    （開発時に実際に確認済みの不具合パターン。9章のトラブルシュートも参照）。
    VS Code / PowerShell ISE 等、エンコーディングを明示できるエディタでの編集を推奨する。
  - 確認コマンド（`config.local.ps1` を編集した直後は最低限これを確認する。
    先頭3バイトが `239 187 191` であればBOM付きUTF-8）:
    ```powershell
    $b = [System.IO.File]::ReadAllBytes("config.local.ps1")[0..2]
    "$($b[0]) $($b[1]) $($b[2])"
    ```
  - キット一式を展開・移動した後や、他のファイルも編集した場合は、フォルダ内の
    **全 `.ps1` を一括確認**すると安心（1本でもBOM無しになっていると、そのファイルの
    実行時にだけ日本語部分で構文エラーが出るため、個別確認だと見落としやすい）:
    ```powershell
    Get-ChildItem -Path . -Filter "*.ps1" -Recurse | ForEach-Object {
        $b = [System.IO.File]::ReadAllBytes($_.FullName)[0..2]
        $isBom = ($b[0] -eq 239 -and $b[1] -eq 187 -and $b[2] -eq 191)
        [PSCustomObject]@{ File = $_.FullName; BOM = $isBom }
    } | Format-Table -AutoSize
    ```
    `BOM` 列が全行 `True` であることを確認する。`False` の行があれば、該当ファイルを
    `config.sample.ps1` 等から作り直すか、エディタでBOM付きUTF-8として保存し直す。

## 4. 初回本実行（-Backfill）

- □ 3章のDryRun結果をクライアントと確認済みであることを再確認した
- □ 以下を実行した:
  ```powershell
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Save-MailAttachments.ps1 -Backfill
  ```
- □ 実行が完了するまで待った（目安: 対象メール数・添付サイズに依存。数十〜数百通規模で数分〜数十分程度を見込む。
  進行中は `logs\run-YYYYMM.log` を `Get-Content -Wait` 等で監視すると安心）
- □ 完了後、保存件数のポップアップが表示されたことを確認した（0件保存の場合はポップアップが出ない仕様のため、
    その場合はログで保存0件だったことを確認する）
- □ **検収手順（冪等性の実地証明）:** 直後にもう一度 DryRun を実行し、「保存予定ファイル数」が
    **0件**（＝対象添付が全件スキップ見込み）になることを確認した:
  ```powershell
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Save-MailAttachments.ps1 -DryRun
  ```
  0件にならない場合は、直前の`-Backfill`実行が完全に終わっていない（対象期間内にまだ処理していない
  メールが残っている）か、何らかの理由で保存に失敗した添付がある可能性があるため、ログを確認すること。
  ※このDryRunのスキップ見込みは概算（att.Sizeベース）である点に注意。数件のズレは概算の性質上あり得るが、
  「明らかに大半が保存予定のまま」であれば異常のサインとみなす。

**補足:** 前回試作が既に作成済みの635フォルダ群は、削除・移行しなくてもそのまま活きる。
本ツールは「保存先に同名かつ実サイズ・ハッシュが一致するファイルが既にあればスキップ」する冪等性を持つため、
既存フォルダに重ねて実行しても重複ファイルは増えない（REQUIREMENTS.md 仕様7参照）。

## 7. 運用説明（クライアントに伝えること）

- □ ポップアップの意味: 「添付ファイルをN件保存しました」＋フォルダ名一覧。手動で閉じるまで消えない。
    エラーではなく正常完了の通知であることを伝えた
- □ ログの場所（`logs\run-YYYYMM.log`）を伝え、何か気になることがあれば月次でこのファイルを見れば
    履歴が追えることを伝えた
- □ 失敗時の挙動: 1通単位でエラーが出ても他のメールの処理は止まらず、失敗したメールだけ次回また
    自動的にリトライされることを伝えた（＝連絡不要で自然に解消するケースが多い旨）
- □ 管理コードのパターンを追加したくなった場合は、`config.local.ps1` の `$SubjectPatterns` に
    1行追加するだけで良いことを伝えた（追加後は動作中のOutlookは再起動不要。次回のタスク実行から反映される）
- □ 上記いずれも本手順書と `README.md` に記載があることを伝えた

## 8. 既知の経緯メモ（クライアント・後任者向け）

- 過去の一括処理（前回試作）で作成済みの635件規模のフォルダ群は、**原則そのまま活用して問題ない**。
  本ツールはフォルダ名やファイルの重複を壊さない設計になっている
- 前回試作の初回実行で誤って既読化された22通について、**どのメールだったかの特定記録が残っておらず、
  未読状態への復元は現実的ではない**。今回の完成版はメール本体（既読/未読状態含む）を一切変更しない
  設計にしており、同種の事故は起きない
- 保存先ルートのフォルダ構成を「コード形式」と「その他（旧形式の疑い）」に仕分けて棚卸ししたい場合は
  `Cleanup-Inventory.ps1` を使う（既定では一覧表示のみで何も削除しない）:
  ```powershell
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Cleanup-Inventory.ps1 -Root "Z:\<保存先パス>"
  ```
  出力される `logs\cleanup-inventory-<日時>.csv` をクライアントと一緒に確認し、
  「その他」に分類されたフォルダの扱い（放置／別途アーカイブ／削除）を相談すること。
  削除する場合も `-Delete -Confirm` の両方の指定と削除件数の入力確認が必要な二重ゲート方式になっている
  （詳細はスクリプト冒頭のコメントを参照）
- 「コード形式」の判定パターンは `config.local.ps1` の `$SubjectPatterns` から自動的に導出される
  （実行時にコンソールへ表示される）。7章の運用で `$SubjectPatterns` にパターンを追加した場合、
  `Cleanup-Inventory.ps1` 側の分類はそれに自動追従するため、このツールを個別に修正する必要はない

## 9. トラブルシュート

| 症状 | 確認・対処 |
|------|-----------|
| ポップアップも出ずログも増えない | タスクスケジューラで `MailAttachSaver` が「準備完了」状態か確認。Outlookが起動しているか確認（Outlook未起動時は仕様どおり何もしない） |
| ログに「Outlookが起動していない」旨だけが延々と記録される | Outlookが実際に起動しているか、常駐トレイに隠れていないか確認。Outlookを一度完全に終了→再起動してみる |
| ログに「保存先ルートが見つからない」旨が記録される | `Test-Path` で `$SaveRoot` を確認（Z:の再接続が必要な場合がある）。VPN/社内ネットワーク接続状況も確認 |
| 「新しいOutlook」に切り替わってしまった（トグルがオンになっている） | Outlook右上の「新しいOutlookを試す」トグルをオフに戻し、クラシックOutlookへ戻す。新しいOutlookはCOM非対応のため本ツールは動作しない |
| 実行時に日本語部分で構文エラーが出る | `config.local.ps1` 等がBOM無しUTF-8で保存されてしまった可能性が高い（2章の注意参照）。`config.sample.ps1` をコピーし直し、設定し直すか、エディタでBOM付きUTF-8として保存し直す |
| 権限エラー（アクセスが拒否されました等） | 共有ドライブへの書き込み権限、`logs` フォルダへの書き込み権限を確認。タスクスケジューラのタスクが正しいユーザーで登録されているか確認（`Register-Task.ps1` 実行時の表示を参照） |
| DryRunの対象件数が明らかにおかしい | 3章の注記のとおり、Windowsの地域設定によるOutlook `Restrict` の日付書式ズレを疑う |
| タスクを一時的に止めたい | `Unregister-Task.ps1` を実行してタスクを削除する（再度必要になったら `Register-Task.ps1` を再実行すればよい） |
