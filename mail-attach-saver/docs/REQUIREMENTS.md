# 要件定義書 — Outlook受信メール添付の自動保存ツール

> **要件は前セッションでクライアント側と合意済み。本文書はその写し（ゲート通過記録）。**
> 実装・テスト・ドキュメント作成はすべて本文書の確定仕様に基づく。

## 0. 背景（再発防止の対象となった事故）

物流系クライアントの業務効率化案件。前回試作は現地環境（クラシックOutlook・共有ドライブ）で
動作したが、運用開始直後に次の2件の事故が発生した。

| # | 事故内容 | 影響 |
|---|---------|------|
| a | 一括処理で想定外に大量のフォルダを作成（635通処理） | 保存先ルートに大量の未整理フォルダ |
| b | 初回実行時に22通のメールを誤って既読化 | 対象メールの特定記録が無く復元は現実的に不可能 |

今回はこの2件の再発防止ガードを備えた完成版を、現地導入手順書つきの納品キットとして
新規実装する（旧試作のファイルは手元に無いため流用していない）。

## 1. 確定仕様一覧

| # | 項目 | 内容 |
|---|------|------|
| 1 | 対象メール | Outlook既定プロファイルの受信トレイ。既読/未読を問わない。直近N日（既定90日・設定可）。`Items.Restrict` で `ReceivedTime` を絞り込み、受信トレイ全件走査を避ける |
| 2 | 検知条件 | 件名が正規表現パターン群のいずれかに部分一致（大文字小文字無視）。既定パターンは1本: `(DJ\|BJ\|CH)\d{5}(?!\d)`（DJ/BJ/CH + 数字ちょうど5桁。6桁以上の数字列は誤検知しない）。設定で配列に追加可能 |
| 3 | 複数コード検出時 | 件名内で最も先頭に現れたコードを採用し、複数検出した旨をログに記録する（※未確定点、下記参照） |
| 4 | 添付なしメール | 保存対象の添付が1件以上あるメールのみ処理する。添付が無いメールはフォルダも作らない |
| 5 | フォルダ命名 | 抽出コード + `"_"`（例: `DJ26779_`）。保存先ルート直下に作成。既存の同名フォルダがあれば新規作成せずそこへ追加保存する |
| 6 | インライン画像の除外 | 既定で除外。判定1: `PR_ATTACHMENT_HIDDEN`(`0x7FFE000B`) が `true`。判定2(フォールバック): `PR_ATTACH_CONTENT_ID`(`0x3712001F`) が取得できかつ `HTMLBody` 内に `cid:<ID>` 参照がある。いずれの判定も取得失敗時は「除外しない」安全側に倒す。設定 `$ExcludeInlineImages` で無効化可能 |
| 7 | 冪等性（事故復旧の要） | [レビュー反映] COMの`Attachment.Size`はMAPI `PR_ATTACH_SIZE`由来で実際の添付内容より大きいことがある（Microsoft公式に明記）ため、att.Sizeのような近似値に頼らず、添付をまず`logs\tmp`の一時ファイルへ書き出してから実際のファイルサイズ・MD5ハッシュで判定する。保存先に同名・同実サイズ・同ハッシュのファイルが既にあればスキップ（保存済み扱い。一時ファイルは破棄）。同名で実サイズが異なる場合、または実サイズが同じでもハッシュが異なる場合（安全側）は`name (2).ext`形式の連番で保存。旧試作が既に作成済みの635フォルダに重ねて実行しても重複ファイルは増えない |
| 8 | 重複防止の主軸 | 処理完了メールの EntryID を `logs\processed-ids.txt` に1行1件で追記し、以後スキップする。ログが消えても仕様7が二重の防御になる |
| 9 | メール本体の不可侵 | `UnRead` への代入禁止・`.Save()` 禁止・移動/削除禁止。既読/未読状態は一切変更しない |
| 10 | 処理件数の上限ガード | [レビュー反映] 上限 `$MaxMailsPerRun`（既定50・古い順）は「件名がコードに一致し、かつ保存対象の添付がある候補」にのみ適用する（保存作業量の上限）。コード不一致・添付なしのメールは保存作業を伴わないため上限を消費せず、その場で処理済み記録してよい（実測1〜3秒/100通と評価コストは低い）。当初は上限を受信トレイの未処理メール全体に適用していたが、実機リハーサルで「新しく届いたコード一致メールが古いコード不一致メールに上限を先食いされる」事故が判明したため変更した。超過分は処理せず、残り件数をログと通知に明記する。`-Backfill` スイッチ指定時のみ上限を解除する |
| 11 | DryRun | `-DryRun` 指定時はフォルダ作成・保存・processed-ids追記・通知を一切行わず（一時ファイルも作らない）、対象メール数／作成予定フォルダ／保存予定ファイル数／スキップ見込みをコンソールとログに出力する。[レビュー反映] 実サイズ・ハッシュ判定は`SaveAsFile`を伴うためDryRunでは行えず、`att.Size`による概算判定になる旨を出力に明記する |
| 12 | エラー処理 | メール1通単位で try/catch。失敗はログに残して処理を継続し、`processed-ids.txt` には書かない（＝次回自動リトライ） |
| 13 | 完了通知 | 1件以上保存した実行のみ、手動で閉じるまで消えないポップアップを表示（`WScript.Shell` の `Popup` を timeout 0 で）。内容は保存件数＋フォルダ名一覧（6件超は先頭5件＋「他n件」）。DryRun時・0件保存時は出さない。設定でOFF可。[レビュー反映] 実機リハーサルで表示有無をログから判別できない問題が判明したため、表示直前に必ず`通知表示: 保存n件`をログへ記録する。また見落とし防止のためシステムモーダル（`vbSystemModal`=4096を加算）にして最前面表示を試みる |
| 14 | Outlookへの接続 | `[Runtime.InteropServices.Marshal]::GetActiveObject("Outlook.Application")` で「起動中のOutlook」にのみ接続する。未起動ならOutlookを起動させず、ログに1行残して静かに終了する（タスクスケジューラから5分毎に呼ばれる前提で次回に任せる） |
| 15 | 実行ログ | `logs\run-YYYYMM.log` に毎回追記。開始/終了・件数・スキップ・エラー・上限超過を記録する |
| 16 | 名前のサニタイズ | Windowsのファイル名・フォルダ名禁止文字は `_` に置換。末尾のドット/空白は除去し、空になった場合は `attachment` とする。フルパスが250文字を超える場合は拡張子を保持したままファイル名を切り詰め、切り詰めた旨をログに記録する |
| 17 | 文字エンコーディング | Shift_JIS/CP932環境でも壊れないよう、`.ps1` はすべて BOM付きUTF-8 で保存する（日本語コメント・日本語ポップアップがあるため必須。BOM無しUTF-8だとWindows PowerShell 5.1がCP932として誤読し、日本語部分の文字化けから構文エラーになることを開発時に実際に確認している） |

## 2. MailAttachLib.ps1 の純粋関数（テスト対象・Outlook非依存）

| 関数名 | 役割 |
|--------|------|
| `Get-CodeFromSubject` | 件名から管理コードを抽出（先頭マッチ採用・複数検出フラグ） |
| `ConvertTo-SafeName` | ファイル名・フォルダ名のサニタイズ |
| `Get-SaveFileName` | 保存先の実フォルダを見て、実サイズ・実ハッシュ（引数で受け取る）を基にスキップ／連番／そのまま を判定。[レビュー反映] スキップ時は`-MatchedName`（任意の`[ref]`）で実際に一致したファイル名（連番側のこともある）を返せる |
| `Limit-PathLength` | フルパス250文字超の切り詰め（拡張子保持） |
| `Select-MailsToProcess` | 古い順に上限適用・残件数の算出 |
| `Test-InlineAttachment` | インライン画像（署名画像等）の除外判定 |
| `Initialize-TargetFolder` | [レビュー反映] フォルダ作成の書き込み系統。`-DryRun`指定時は作成せず既存有無だけ返す |
| `Add-ProcessedId` | [レビュー反映] processed-ids追記の書き込み系統。`-DryRun`指定時は追記しない |
| `Save-AttachmentToTarget` | [レビュー反映] 添付保存の書き込み系統。実際の書き込み処理はスクリプトブロック(`-WriteTempFile`)として注入させることでOutlook非依存を保っている。`-DryRun`指定時は一時ファイルも作らずatt.Sizeベースの概算判定のみ返す |
| `Show-SaveNotification` | [レビュー反映] 完了通知の判定ロジック（出すか出さないか・メッセージ内容）。実際にポップアップを表示する処理はスクリプトブロック(`-ShowPopup`)として注入させ、テストではモックに差し替えられる |

すべて `tests\Run-Tests.ps1` で合成データによる検証済み（Outlook・ネットワーク不要）。
`Save-AttachmentToTarget` は `Attachment.SaveAsFile` の代わりに `Set-Content` を注入した
偽の書き込み処理で、一時ファイル経由フロー全体（本実行時の冪等スキップ・連番保存・DryRun時の
不変条件）を検証している。

## 3. 現地確定項目（現地導入時にクライアントと確定させる項目）

| 項目 | 現状の扱い | 現地での確定方法 |
|------|-----------|-------------------|
| 遡及日数（既定90日）の最終値 | `config.local.ps1` の `$RetentionDays = 90` を仮設定 | `docs\ONSITE-SETUP.md` 手順3のDryRunで対象件数・期間を提示し、クライアントと確認のうえ確定する |
| 件名パターンの追加有無 | 既定1パターンのみ（`(DJ\|BJ\|CH)\d{5}(?!\d)`） | 現地でクライアントに他の管理コード体系が無いか確認し、あれば `config.local.ps1` の `$SubjectPatterns` に追加する |
| 旧形式フォルダ（前回試作が作成した635件を含む）の扱い | そのまま活用する方針（削除・移行はしない） | `Cleanup-Inventory.ps1` で棚卸しし、コード形式/その他の内訳をクライアントと確認する。詳細は `docs\ONSITE-SETUP.md` 8章 |
