# mail-attach-saver — Outlook受信メール添付の自動保存ツール

Outlook（クラシック版）の受信トレイを監視し、件名から抽出した管理コードごとに
添付ファイルを共有ドライブ上のフォルダへ自動保存するツール一式。

物流系クライアント向け業務効率化案件の納品キット。前回試作で発生した
「想定外の大量フォルダ作成（635通一括処理）」「初回実行での誤既読化（22通）」の
再発防止ガードを備えた完成版。

## 概要

- Outlookは「起動中のインスタンス」にのみ接続する（未起動なら何もせず終了）
- 受信トレイ直近N日分を対象に、件名の管理コード（既定: `DJ`/`BJ`/`CH` + 数字5桁）を検知
- 該当メールの添付ファイルを `<保存先ルート>\<コード>_\` へ保存する
- タスクスケジューラで5分間隔の自動実行を想定（Outlook起動時のみ実際に動作する）
- メール本体（既読/未読・内容・保存場所）は一切変更しない

## 設定一覧（config.local.ps1 / config.sample.ps1）

| 設定名 | 既定値 | 内容 |
|--------|--------|------|
| `$SaveRoot` | プレースホルダ | 添付ファイルの保存先ルートフォルダ（例: `Z:\<保存先ルートのパス>`） |
| `$RetentionDays` | 90 | 受信トレイの遡及日数 |
| `$SubjectPatterns` | `@('(DJ\|BJ\|CH)\d{5}(?!\d)')` | 件名検知パターン（正規表現の配列） |
| `$ExcludeInlineImages` | `$true` | インライン画像（署名画像等）を保存対象から除外するか |
| `$MaxMailsPerRun` | 50 | 1回の実行で処理するメール数の上限（`-Backfill`で解除） |
| `$EnableNotification` | `$true` | 保存完了時のポップアップ通知を出すか |
| `$ProcessedIdsPath` | `logs\processed-ids.txt` | 処理済みEntryIDの記録先 |
| `$LogFolder` | `logs\` | 実行ログの保存先フォルダ |

## 動作フロー

- タスクスケジューラが5分毎に `Save-MailAttachments.ps1` を起動する
- 起動中のOutlookが見つからなければ、ログに1行残して即終了する
- `$SaveRoot` が存在しない／パスが不正な場合は処理を中断する（Z:未接続や設定ミスの検知）
- 受信トレイを `Items.Restrict` で直近N日に絞り込み、`processed-ids.txt` 記載分を除外する
- 古い順に `$MaxMailsPerRun` 件まで選び、1通ずつ次を行う
  - 件名から管理コードを検知（無ければ処理済みとして記録しスキップ）
  - インライン画像を除いた添付が無ければ、フォルダを作らずスキップ
  - `<コード>_` フォルダへ、添付をまず `logs\tmp` の一時ファイルへ書き出し、実サイズ・MD5ハッシュが
    既存ファイルと一致すれば一時ファイルを破棄してスキップ、異なれば連番名で移動して保存する
  - 保存後、EntryIDを `processed-ids.txt` に追記する（メール本体には触れない）
- 1件以上保存した実行のみ、閉じるまで消えないポップアップで結果を通知する

## 再発防止ガードの説明

前回試作の事故（635通一括処理・22通誤既読化）を踏まえ、以下のガードを実装している。

| ガード | 内容 |
|--------|------|
| 処理件数上限（既定50・古い順） | 一度に大量のメールを処理して想定外のフォルダが大量発生する事故を防ぐ。`-Backfill`を明示しない限り上限を超えない |
| `-DryRun` | 実際の保存・フォルダ作成・記録・通知を一切行わず、対象件数と保存予定件数を事前に確認できる。現地導入手順（ONSITE-SETUP.md）では本実行前に必ずDryRunを行う運用にしている |
| 冪等スキップ（実サイズ・ハッシュ一致は保存しない） | 一時ファイルへ書き出した実際のサイズ・MD5ハッシュで既存ファイルと比較するため、同じ処理を何度実行しても重複ファイルが増えない。COMのAttachment.Size（MAPI PR_ATTACH_SIZE）は実際の添付内容より大きいことがあり近似値でしかないため、att.Sizeだけに頼らず実サイズ・実ハッシュで判定するようにしている。前回試作が既に作成した635フォルダに重ねて実行しても安全 |
| EntryIDによる処理済み記録 | 一度処理したメールを二重に処理しない（冪等スキップと合わせた二重防御） |
| メール本体の不可侵（既読化・移動・削除の禁止） | `UnRead`への代入・`.Save()`・移動・削除を一切行わない。誤既読化事故の再発を構造的に防止する |
| 単一起動の保証（ミューテックス） | タスクスケジューラの実行間隔（5分）より処理が長引いた場合に、多重起動で処理が重複するのを防ぐ |
| メール1通単位のエラー処理 | 1通の処理に失敗しても他のメールの処理を止めず、失敗したメールだけ次回自動リトライする |

## 保守者向け注意

`Save-MailAttachments.ps1` 本体の `-DryRun` 分岐（フォルダ作成・添付保存・processed-ids追記の
呼び出し方）を変更した場合は、`tests\Run-Tests.ps1` の「DryRun不変条件」テスト
（`Initialize-TargetFolder` / `Save-AttachmentToTarget` / `Add-ProcessedId` を `-DryRun:$true` で
呼んでもファイル/フォルダが1つも増減しないことを検証するテスト）を必ず再実行し、全PASSを確認すること。
DryRunは現地手順（ONSITE-SETUP.md）で「クライアントに見せて確認を取る」役割を担っており、
DryRunなのに実際にファイルへ書き込んでしまう再発は事故に直結するため、他のテストより優先して守ること。

## 開発・検証について

この開発機にはOutlookプロファイルも共有ドライブ（Z:）も無いため、`Save-MailAttachments.ps1`
本体・`Register-Task.ps1`・`Unregister-Task.ps1` は実機での動作確認ができない。

- 開発機で実施済み: `MailAttachLib.ps1` の純粋ロジックに対する合成テスト（`tests\Run-Tests.ps1`、全PASS。
  添付保存は `Attachment.SaveAsFile` の代わりに `Set-Content` を注入した偽の書き込み処理で
  一時ファイル経由フロー全体を検証）、全 `.ps1` の静的構文チェック、`Cleanup-Inventory.ps1` の
  一時フォルダによる動作確認（config連動の分類パターン導出を含む）
- 開発機では実施できない（現地でのみ可能）: Outlook COM接続・共有ドライブへの実保存・タスクスケジューラ登録・
  ポップアップ通知の実機確認

実機での検証手順は `docs\ONSITE-SETUP.md` のチェックリストに従うこと。DryRun → `-Backfill`本実行 →
通常実行テスト → タスクスケジューラ登録の順で、各段階を確認しながら進める設計になっている。
